# Replay JSON contract

The files `runs/run-NN/replay.json` and `examples/replay-*.json` use the same run-level envelope. The examples are generated by `replayRun()` and the production scorer; they demonstrate the UI shape and are not evaluation records.

## Root object

| Field | Meaning |
| --- | --- |
| `schema_version` | Replay schema version; currently `"1.0"`. |
| `run_id` | Numeric evaluation run number, or `null` for synthetic examples. |
| `session_id` | TrueForge session ID, or `null` for synthetic examples. |
| `synthetic` | `false` for an actual evaluation export; `true` for generated interface examples. |
| `contract_sha256` | Fingerprint of the task JSON, task/prompt contract code, and scorer code used to produce the replay. |
| `summary` | Aggregate run score, passed task count, and total task count. `score` is on a 0–100 scale. |
| `tasks` | One replay record per task, in evaluation order. Synthetic examples contain one task. |

## Task record

Each object in `tasks` includes `schema_version`, `run_id`, `session_id`, and `synthetic` copied from the root, followed by:

| Field | Meaning |
| --- | --- |
| `task` | Model-visible task context: ID, title, target, scenario, and recorded observations. Expected answers and holdout status are omitted. |
| `parsed_answer` | Parsed agent verdict and findings, or `null` when the complete response failed JSON/schema validation. |
| `scoring` | Per-task deterministic diagnostics described below. |

`scoring.score` is per-task on a 0–1 scale, unlike `summary.score` on a 0–100 scale. `passed` requires the exact expected verdict and finding set. `precision`, `recall`, and `finding_f1` use exact category plus full evidence-ID-set matches. `matched`, `missed`, and `noise` contain scorer-only explanations and reference details for the replay UI; they must never be sent back as part of a model task prompt. `error` is `null` unless parsing or evidence-ID validation reported an error.

## Synthetic examples

The example generator uses a fictional fixed task and the same scorer as evaluation runs. One record is a perfect synthetic answer and one is a partial synthetic answer. Both have `synthetic: true`, `run_id: null`, and `session_id: null`. Their citations and expected-side diagnostics are illustrative fixture data, not measurements or live security findings.
